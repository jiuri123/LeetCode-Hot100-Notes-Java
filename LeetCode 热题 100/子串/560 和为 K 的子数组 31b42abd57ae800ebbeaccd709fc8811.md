# 560. 和为 K 的子数组

[https://leetcode.cn/problems/subarray-sum-equals-k/description/?envType=study-plan-v2&envId=top-100-liked](https://leetcode.cn/problems/subarray-sum-equals-k/description/?envType=study-plan-v2&envId=top-100-liked)

## 方法一

使用前缀和的解法，大概思路就是先计算出原数组的前缀和数组preSum，然后遍历这个前缀和数组preSum。每遍历到一个前缀和preSum[i]，就去查找这个前缀和之前有没有出现过前缀和为preSum[i] - k这个值，如果出现过，就说明存在一个或多个子数组（这个子数组以nums[i - 1]为结尾），该子数组的和为k。此时我记录出现过前缀和为preSum[i] - k这个值的前缀和个数，这个个数就表示当前这个前缀和之前，和为k的子数组的个数。把这个值不断地累加，直到遍历完前缀和数组preSum[i]，那么最后累加得到的结果就是该数组中和为 `k` 的子数组的个数。

查找前缀和preSum[i] - k出现的个数的时候，可以通过map来查找，也就是说遍历前缀和的同时，将该前缀和存储到map中，方便后面的前缀和进行查找。

为什么这样可行呢？因为当前的前缀和preSum[i]表示的意思是0~i-1这些位置的元素所构成的子数组的和，而如果之前出现过前缀和为preSum[i] - k的这个值，假设这个前缀和为preSum[i] - k的结尾所在的位置是j，那么也就是说0~j-1这些位置的元素所构成的子数组的和为preSum[j]，即preSum[i] - k。此时可以看到preSum[i] - preSum[j] = preSum[i] - （preSum[i] - k） = k，也就是说j~i-1这些元素所构成的子数组的和为k，这样就找到了一个和为k的子数组。

整体代码如下：

```java
// 方法一：先提前计算好前缀和，需遍历两次
class Solution {
    public int subarraySum(int[] nums, int k) {
        int n = nums.length;
        int[] preSums = new int[n + 1];

        // 提前计算前缀和
        for(int i = 1; i < n + 1; i++){
            preSums[i] = preSums[i - 1] + nums[i - 1];
        }

        int ans = 0;
        // HashMap 存储形式：{前缀和 : 该和出现的次数}
        Map<Integer, Integer> cnt = new HashMap<>();
        for(int preSum : preSums){
            // 查找之前是否出现过preSum - k的前缀和，并返回其个数
            ans += cnt.getOrDefault(preSum - k, 0);
            // 等同于cnt.put(preSum, cnt.getOrDefault(preSum, 0) + 1);
            cnt.merge(preSum, 1, Integer::sum);
            // preSum (Key)：你要操作的键。
						// 1 (Value)：默认值。如果 Map 里还没这个 Key，就直接把这个 1 存进去。
						// Integer::sum (BiFunction)：合并函数。
						// 如果 Map 里已经有这个 Key 了，就用这个函数把“旧值”和“新值（第二个参数 1）”合并。
        }
        return ans;
    }
}

```

## 方法二（推荐，方法一改进版）

其实不需要提前计算好前缀和，可以直接在遍历原数组的同时就计算前缀和并查找，这样可以省掉一次遍历的时间，而且也不需要额外的存储空间来保存各个位置的前缀和。代码如下：

```java
// （推荐）方法二：遍历原数组的时候在计算前缀和，只需遍历一次
// 时间复杂度：O(n)
// 空间复杂度：O(n)
class Solution {
    public int subarraySum(int[] nums, int k) {
        // count 记录符合条件的子数组个数
        int count = 0;
        // preSum 记录当前遍历到的前缀和
        int preSum = 0;
        
        // HashMap 存储形式：{前缀和 : 该和出现的次数}
        Map<Integer, Integer> map = new HashMap<>();
        
        // 【核心点】初始化：前缀和为 0 默认出现 1 次
        // 处理那种“正好从数组第一个元素开始，和就等于 k”的情况
        map.put(0, 1);
        
        for (int num : nums) {
            preSum += num;
            
            // 如果 map 中存在 preSum - k，说明找到了符合条件的子数组
            // 下面的 if 也可以简化成 count += map.getOrDefault(preSum - k, 0);
            if (map.containsKey(preSum - k)) {
                count += map.get(preSum - k);
            }
            
            // 更新当前前缀和出现的次数
            map.put(preSum, map.getOrDefault(preSum, 0) + 1);
        }
        
        return count;
    }
}
```

易错点

1. 需要先执行cnt.put(0, 1)，为什么？举例：
- 假设 `nums = [3, 2, 1]`，`k = 3`。
- 当遍历到第一个数 `3` 时，`preSum = 3`。
- 我们需要查找 `preSum - k = 3 - 3 = 0`。
- 如果表里没有 `0`，那我们就漏掉了这个从头开始的子数组。

`put(0, 1)` 的本质意义是：前 0 个元素的和为 0，这种情况已经出现过一次了。如果没有这句代码，会导致起始点为原数组第一个元素的那些子数组全部没有被找到，使得结果偏小。

1. 能不能使用双指针（滑动窗口）解法？

在**包含负数的情况**下，不能使用传统的双指针（滑动窗口）解法。虽然双指针在处理“子数组和”问题时很常见，但它是有严格前提条件的。原因：

- 如果数组元素全部为正数：
    - 当窗口和 sum < k 时，我们右移右指针，窗口和必然增加。
    - 当窗口和 sum > k 时，我们右移左指针，窗口和必然减少。
    - 这种确定的增减方向让我们可以通过移动边界来逼近目标值。
- 如果数组包含负数（本题情况）：
    - 根据题目提示，nums[i] 的范围是 [-1000, 1000]。
    - 当你右移右指针时，窗口和可能增加（遇到正数），也可能减少（遇到负数）。
    - 当你右移左指针时，窗口和可能减少，也可能增加。
    - 结论： 左右指针的移动不再具有预测性，窗口无法通过简单的缩放来覆盖所有可能的结果。
